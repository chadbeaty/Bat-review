# Track C: the bat database (Phase 6)

Model pages, the price guide, comparison, manufacturer pages and the new-bat features (lineage, release status,
First Swings owner reports, durability tracker, review alerts, watchlist).

## Pages

| Route | What it shows |
| --- | --- |
| `/bats/[manufacturer]/[model]/[year]` | One model (model + year + stamp). Header with stamps, release badge and key specs; spec table with verification status per spec and the source link; warranty; asking and sold prices (kept apart) with breakdowns by weight and condition and a trend chart; active listings; "What changed from last year"; published reviews (this model, its predecessor, its line); First Swings summary, form and latest check-ins; durability tracker; review alerts and watchlist; reviewed alternatives; same-line models; Product JSON-LD (no ratings or offers). 404 for anything unknown. |
| `/price-guide` | How asking and sold prices differ, the thresholds (read from `site_settings`), and every model with active-listing count, current asking-price range and number of verified sales. Search plus brand, year and stamp filters (plain GET form, works without JavaScript). |
| `/compare?models=a,b,c` | 2–3 models side by side from a field list (`batCompareFields`); rows whose known values differ are highlighted. Add with the picker (redirects to one shareable `?models=` URL), remove per model. "Not listed" never counts as a difference. No performance fields. |
| `/manufacturers/[slug]` | A brand's models grouped by year, then line, with the warranty line. `/manufacturers` links to these. |
| `sitemap.xml` | Adds `/compare`, every manufacturer page and every model page (from the database, or `src/data/catalog-fallback.json` without one). |

Model URLs come from `batModelPath`; lookup matches manufacturer slug, year and `modelSegment(slug)` exactly (the query uses `productSlugPattern`, plus the bare segment for the few slugs that don't end in their year, such as `anderson-rocketech-alloy-dual`).

## Data

Migration `supabase/migrations/20261102000300_bat_database.sql` (additive, re-runnable):

- `product_lines` (from `data/families.json`) and `products.product_line_id` (from each bat's `family` in `data/bats.json`).
- `products.lineage_note` jsonb: `{predecessor_name, predecessor_in_catalog, changes[], confidence, basis, sources[], researched_on}` for all 117 entries in `data/lineage.json`, so predecessors outside the catalog are still shown by name.
- `products.release_date_source`. The research notes contain no documented release date for any model, so none are set and every model shows "Release date not on file".
- `manufacturers.warranty_summary`, `warranty_source`, `warranty_source_url` (Easton, Miken, Worth, DeMarini, Monsta from `docs/NEW-BAT-RESEARCH.md`; others null → "Warranty terms not on file").
- `published_reviews` + `published_review_products` + `published_review_lines` (from `data/reviews.json`). Public read (hidden reviews and links to unpublished models are filtered), no write grants or policies for browsers: only the server writes.
- View `product_market_summary`: per published product, active-listing count and asking min/max/avg, and verified-sale count and date range, in separate columns.

Seed `supabase/seed/bat-database.sql` is generated by `scripts/build-bat-database-seed.mjs` (also run by `npm run catalog:seed`). It fails if any lineage or review reference doesn't resolve. Lineage rows: in-catalog predecessors as `predecessor`; siblings as `variant` when our catalog specs are identical, otherwise `same_platform`; all `verified = false` with the file's confidence and basis. The seed is listed in `supabase/config.toml` and in `tests/db/harness.ts`.

Queries live in `src/lib/bats.ts` (server only). Pure logic, shared with tests: `src/lib/price-stats.ts`, `src/lib/compare.ts`, `src/lib/bat-display.ts`, `src/lib/owner-reports.ts`. Member actions: `src/app/bats/actions.ts` (zod-validated, signed-in user required, RLS-scoped client).

## Honesty rules implemented

- Asking and sold prices are separate blocks with the brief's labels ("Current asking-price range", "Average current asking price", "Actual average completed sale price", "Number of verified sales", "Date range covered"); no number combines them.
- Sold prices only from `price_history` with `verified_transaction`; the code filters again even though RLS already does.
- Thresholds from `price_guide_min_sales` / `price_guide_full_sales`: below min → "Not enough verified sales yet" (no figures, no chart); min..full-1 → indicative range, small-sample warning, no average (chart dots only); ≥ full → average, range and monthly average line. Breakdowns by weight and condition apply the same thresholds per group.
- Stats are per product (model + year + stamp), never across models.
- Specs are labeled unverified retailer data with a per-spec status; unknown values say "Not listed"; length is marked as the standard length, not confirmed.
- Lineage carries its confidence label ("an assumption" unless high), basis and sources; predecessor reviews are titled "Reviews of the <predecessor>" with a note that they aren't of this bat; line reviews say they may cover other versions.
- Published reviews show the source's own rating text only. No scores, rankings or "hits farther" claims; alternatives are described as alike specs, not alike performance.
- First Swings: each owner counts once (latest check-in); small samples are flagged; the durability tracker only appears at `durability_min_owners`. Reports show "Owner" or "Verified owner", never usernames or user ids.
- JSON-LD has no ratings or offers.

## Limitations

- No release dates are on file, so release badges all read "Release date not on file" until someone adds dated sources (`release_date`, `release_status`, `release_date_source`).
- Review alerts and watchlist rows are stored, but nothing sends notifications yet (the notifier belongs to the notifications work).
- First Swings has no proof-photo upload yet; ownership is verified automatically from completed marketplace orders (database trigger).
- Listing cards link to `/listings/[id]`, which another track builds.
- Price-guide filtering happens in the server component over all models (121 today); move it into SQL if the catalog grows into the thousands.
- No warranty source URLs were documented, so only the summary and a "check current terms" note are shown.
